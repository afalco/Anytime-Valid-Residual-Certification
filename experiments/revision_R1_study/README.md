# Frozen R1 numerical study

`protocol.json` fixes the design before production runs. The scientific settings
are not adjusted based on the resulting ranks, failures, or costs. The first
bounded preflight was used only to check runtime, checkpointing and memory.
The official run uses `revision_R1/production_v1_full/`, distinct from preflight.

From the repository root, with the anytime-qb environment active:

```bash
python experiments/revision_R1_study/run_production.py \
  --data-dir /absolute/path/to/real_matrix_study/data \
  --out-dir experiments/revision_R1_study/revision_R1/production_v1_full
python experiments/revision_R1_study/run_exact.py \
  --out-dir experiments/revision_R1_study/revision_R1/production_v1_full
```

Requirements are listed at the repository root. `threadpoolctl` limits supported
BLAS libraries to one thread; the detected thread pools and versions are archived.
Do not run concurrent CPU-intensive tasks when collecting timings.

The production driver saves a manifest with protocol, source and data SHA256 hashes,
versions and thread settings. It refuses to append results if provenance differs.
Each completed method trial is flushed to an append-only JSONL checkpoint; CSV and
an explicit complete/incomplete status are also emitted per group. Restarting the
same command skips completed case identifiers. `--groups` selects a stage;
`--max-cases` bounds a preflight without calling it a completed study. Nonfinite
certificates are explicit `Infinity` strings in checkpoints, not missing values.

## Studies

- Coverage: 500 trials per spectrum, n=80, b=1, s=3, alpha=0.25, oracle rho,
  naive and anytime power. Infinity and rank-cap outcomes are retained.
- Rank/oracle sensitivity: original-size diagnostics rerun on the revised engine.
  They explicitly form residuals and are not cost benchmarks.
- Sensitivity: 100 trials, n=120, b=5, cap=100, rho=1, two spectra, s in 32/80/200,
  alpha in .10/.05/.01, power and finite-horizon uniform (3600 method trials).
- Adaptive-size comparison: same two spectra, alpha=.05, minimum s=32, c=16,
  both schedules, 100 trials, kept separate from fixed-size sensitivity.
- Cost baseline: four synthetic profiles, 40 trials, energy/incremental,
  naive/final, anytime/final and anytime/incremental, with matched Q prefixes.
- Stored matrices: all seven benchmark/application inputs, 20 trials per rule;
  energy, naive, power and uniform. Direct stored-block diagnostics are offline.
- Compressible SuiteSparse LP matrix: 20 trials, relative tolerance .1,
  energy/naive/power and explicit A/AT/B costs.
- Graph stress tests: 10 trials each, tolerance .95, b=10, cap=120, s=200,
  cert batches of 20. Energy/naive/power; cached-energy offline diagnostics avoid
  densifying the huge graph residual. This check is not independent of energy
  stopping, so it is not used to prove floating-point safety of that baseline.

Stored-input solver runs use rho=1; oracle and pilot work are not hidden in counts.
All method trials sharing matrix/trial use the same basis seed, independently of
certification. The same certification seed across size/schedule policies supplies
common randomness without probe reuse within a run; sample blocking and skipped
invalid inspections can change the mapping of those random numbers. Method order
is randomized per matrix/trial. Costs are measured only up to each method's stop.
Norm/validation/loading and offline-work conventions are documented in the energy
baseline README. No method is credited with zero cost for unavailable input norms.

## Exact-law diagnostic

The audit scripts are imported into this repository, not treated as external
pilot evidence. The 20000-trial exact-law study includes analytic stopping
probabilities and a fixed-rank explicit-probe check. `run_exact.py` additionally
executes the identity-matrix QB loop using actual Q updates and fresh probes for
500 trials per naive/power/uniform policy. This is a statistical diagnostic, not
a reason to prefer sketches when the deterministic residual is known.

At full rank the ideal projector residual is zero, while floating-point Q can
leave a tiny numerical residual. Both energies and both miscoverage indicators
are recorded separately; the analytical zero convention must not hide numerical
roundoff or be presented as a general exact-zero detection algorithm.

Figures/tables are generated by `build_artifacts.py` after completeness and
invariant checks, into a separate R1 manuscript directory. Original tables and
figures are never overwritten. These results do not establish a universal best
schedule or a zero failure probability. Report confidence intervals and denominators.

```bash
python experiments/revision_R1_study/build_artifacts.py \
  --results experiments/revision_R1_study/revision_R1/production_v1_full \
  --manuscript-dir /absolute/path/to/project/manuscript/revision_R1
```

Wait for artifact generation to finish before compiling paper_R1.tex. Tables and
figures are replaced atomically, and long stored-cost tables are split into
continuations rather than overflowing a page. Small confidence bounds retain
significant digits so zero-event intervals never appear to have zero width.

Generated tables use `\small` and an `adjustbox` maximum-width constraint.
Narrow tables keep their natural width and are never enlarged; only tables
wider than the available line are reduced. The LaTeX manuscript must load
`\usepackage{adjustbox}`. The follow-up study shares this table generator.
